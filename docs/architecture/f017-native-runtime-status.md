## The supported invocation

```sh
cargo build -p f017-native --release --bin native_generate

./target/release/native_generate \
  --model /path/to/the/six-shard/checkpoint/root \
  --prompt "What is 17 times 6? Answer with the number only." \
  --max-tokens 8
```

The answer goes to stdout; one diagnostics JSON object goes to stderr, so
piping stdout yields exactly the model's text. Useful flags:
`--prompt-file` / `--prompt-stdin`, `--no-chat-template`, `--raw-tokens`
(a labelled diagnostic, not a text result), `--max-prompt-tokens`,
`--max-positions`, `--preflight-only` (identity, tokenizer and template with
no rehash), `--verify-only` (rehash then stop), `--cpu`.

**Known defect, found by Stage B1:** `--no-chat-template` currently supplies an
empty stop set, so a raw-text run always terminates on the output budget rather
than on the model's own terminal. The tokenizer's end-of-generation ids should
apply whether or not the chat template is used. Chat-template runs are
unaffected — they carry the full stop set.

Exit codes are documented in the CLI's own help output.

Bounds and behaviour are frozen in
[`f017-native-temporal-successor-contract-v1.json`](../../specs/017-rust-native-inference-runtime/contracts/f017-native-temporal-successor-contract-v1.json):
greedy only, lowest-token-id tie break, prompt plus output must fit
`max_positions`, `max_positions` may not exceed the checkpoint's indexer
top-k, the identity rehash happens once per session and cannot be skipped,
and no decode rate is reported below the contract's minimum generated length.

The checkpoint root must contain exactly the shards named in the manifest
and nothing else, must not be a symlink, and is opened read-only.

## What this runtime is and is not

It is a correct, bounded, stateful decoder with an honest interface. On the real
checkpoint exactly one result is **qualified**: the receipt banked by the consumed
attempt, which the temporal path reproduces bit for bit. It has since *executed* considerably
more than that, and those executions are **measured**, not qualified: the table
above gives each stage its category and says so in the same row.

Everything multi-token has been qualified on synthetic fixtures against an
independent implementation, which establishes that the state machinery, causality
and numerics are right — not that the real model produces good text, and not how
fast it runs. The distinction this document keeps everywhere is between
*execution*, *qualification* and *formal closeout*: the first has happened for
every stage listed, the second only for that position, and the third not at all.

Relationship to the frozen one-shot: the bounded-P1 admission contract is
terminal and consumed. This runtime is an explicit successor component. It mints
no authority, claims nothing under that contract, and leaves `model.rs`,
`executor.rs`, `contract.rs`, `loader.rs` and `bounded_p1.rs` byte-identical; a
test requires the temporal path at that position to reproduce the single-token
producer bit for bit.
