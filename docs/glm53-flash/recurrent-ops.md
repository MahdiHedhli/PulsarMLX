# Finite recurrent-ops and cache-slot-1 boundary

This research component selects five complete functions, including their original compilation decorators, from Blaizzy/mlx-vlm gated_delta.py at commit `8d79dbcf82a7885ddfc56fb4a55440fa9c5dfb90`. Their exact source spans and ASTs are checked against the complete pinned file. The upstream module is never imported: its import-time custom Metal kernel construction is outside this component.

The default `gated_delta_update` selector is unchanged. The admitted key dimensions 1–4 satisfy its `k.shape[-1] < 32` condition, selecting ordinary ops on CPU and Metal with the original `use_kernel=True` default. A declared raising sentinel closes the excluded kernel arm. Zero observed sentinel calls does not qualify the production kernel.

The separate caller wrapper contains the exact cache[1] read, recurrent call, state write and `advance(S)` statements from PipeNetwork language.py at `a61a7c7d2fbdf3d218a9909365a24bd794f3a247`, lines 289–303. Its parameters expose inputs and the small caller context; the returned `(out,state)` is added for observation. Inputs are synthetic q/k/v, not outputs of upstream projections, convolution or normalization. The actual previously selected ArraysCache and factory are reused. Slot 0 must retain identity and values.

The independent oracle uses Python scalar/list arithmetic, binary64 math and explicit summation. It decays the prior state, projects it onto k, scales the value residual by sigmoid(b), adds the outer product, then projects the updated state onto q. Scalar and per-key vector gates use the independently stated ordinary or safe formula. The source selects masked state after computing y; masked y is not assumed zero. Masks are tested at the ops/update boundary. The exact caller passes no mask, so masked caller behavior is not qualified.

The frozen fixture contains six finite cases, dyadic inputs, complete expected step traces, and an independently propagated FP32 working error budget. Input bounds are B 1–2, T 1–7, Hk 1–2, Hv 1–4 divisible by Hk, and key/value dimensions 1–4. These are finite selected cases, not exhaustive shape coverage. Gate and beta accuracy budgets and output/state tolerances are declared before candidate observation. The budget is a finite acceptance criterion, not a proof of MLX transcendental accuracy.

Each normal, mutant and restored variant receives fresh extracted function objects and compilation decorators. Counters distinguish Python-level source entry calls, returned-step evaluation barriers, outer output barriers, cache observation barriers and target process starts. Compiled tracing, physical operator and kernel execution counts remain unmeasured. The eleven distinct controls cover missing/double decay, residual from the undecayed state, incorrect outer product, head expansion, vector-gate broadcasting, masked-state selection, stale cache state, cross-stream cache aliasing and missing/wrong advance. Detection requires the exact intended assertion after the declared entry and evaluation deltas.

Controlled callee failures qualify only the exact caller's observable ordering. A failing recurrent callee leaves the operated cache unchanged. A failing injected advance callback can observe the returned state already written; this does not claim rollback or qualify the replaced callback as the real advance method. Positive cases separately execute actual advance and subsequent state consumption.

The operation uses the existing successor doctor, descriptor-bound roots, capture, runtime limits, explicit input manifest and regular-file archive format. Research shape/nonfinite refusals occur before candidate entry and are not upstream API guarantees. Source identity, missing/changed fixture, generation and archive-layout refusals remain separate from numerical defects.

Qualification, when supported by retained actual runs and review, is limited to this synthetic ops and unmasked cache1 component. Full KDA projections/normalization, production-shape custom Metal dispatch, full model, weights, quantization, BF16, empty chunks, extreme inputs, streaming, performance and physical I/O remain outside it. The next production-kernel boundary is planning data only.
