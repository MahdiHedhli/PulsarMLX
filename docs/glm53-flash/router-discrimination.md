# Finite router discrimination controls

The current successor adds `discrimination` alongside `doctor`, `case`, `matrix` and `archive-verify`. Use the explicit roles and manifest workflow in [the entry guide](successor-entry.md), selecting `discrimination` with CPU or Metal and a fresh output directory. It runs the working doctor and actual extracted callers, records real captures and stops, builds a portable archive, and performs a fresh data-only readback.

Generation 1 fixes 162 cast cases: two dtypes and a nine-by-nine Cartesian product of input and weight parameters. These include BF16 rounding midpoints, neighboring values, signed values, cancellation and a small residual. Each individual cast is retired only if every case has identical ID-associated caller output bits, exact independent FP32 projection values and the required projection dtype. This is an exhaustive proof over that finite domain only. It does not prove all BF16 matrices equivalent or native BF16/model parity. A genuine actual-caller difference is instead recorded as a discriminating witness; a projection-only difference leaves the claim open.

Six FP32 negative-group cases exercise two, three and four groups, near group-ranking boundaries, and normalized/unnormalized weights through both actual caller classes. The source masks rejected groups with zero. Those zeros can outrank retained negative corrected scores. A clearly named extracted-selector test derivative replaces zero with a finite exclusion sentinel and produces a different expert set. The test preserves that difference; it does not repair production selector behavior or claim generalized group exclusion. The representative configuration uses one group, so that mask branch does not execute.

Three E288/H2 cases keep the representative top eight experts, one group, normalization and scale 2.5. A fixed bias bounded by 1/4096 remains the same while swapping either input columns or weight columns changes the selected experts from 280–287 to 0–7. This demonstrates input/weight dependence in synthetic geometry. Existing bias-dominated fixtures remain unchanged; checkpoint bias and model routing remain unqualified.

The independent oracle uses only the standard library, explicit IEEE rounding and scalar selection. Its exact bytes and the fixture criteria are privately predeclared before candidate outputs. Publication receipts and subsequent launch receipts record operational ordering; they do not create an independent trusted timestamp or alter the historical temporal-custody limitation.

The generic portable-parts format retains its existing schema. This operation additionally requires `successor-discrimination-layout-v1`; its 28 manifested inputs plus eight producer members yield 36 logical files. The reader verifies the layout against the bound producer request and refuses missing or wrong layout. This is an explicit addition to the older 33-file composition, not a forced historical member count.

The source-read trace counts only captured `Path.read_bytes` calls beneath the staged source directory while tracing is active. It excludes `read_text`, guard hashing, and runtime/library I/O. It provides no syscall, physical-disk, page-fault or cold-cache measurement. Historical guard/runner bytes, old numerical definitions/fixtures, protection-policy limitations and missing historical capture/reaping evidence remain unchanged.
