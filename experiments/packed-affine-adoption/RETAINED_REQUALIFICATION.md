## Host use and freeze

Inspect imports and linkage first. No MLX/model imports, native-prefix or
experimental-phase variables, dependency installation or archived executable
execution are permitted. Build the existing `grade-rust` from exact C offline,
locked, no-default-features with at most two Cargo jobs. Record Cargo artifact
selection, source/build/toolchain identity, current executable hash and MLX-free
`otool -L` output separately from the historical CI grader.

`retained_qualify.py admit` performs read-only admission, with no numerical output
grading. Supply `--archive`, `--artifact` (fresh extracted root), `--source`
(exact C), `--controller` (exact H), `--inputs` and `--input-manifest` (the original
46-file inventory). The source/input/artifact aliases are a separate resolution
table; receipt objects are not rewritten, and native/runtime aliases cannot be
resolved to fabricated local files.

Run the explicitly selected host tests, setting `RUST011_EVIDENCE` to the owned
external evidence root and `RUST011_C_SOURCE`/`RUST011_H_SOURCE` to the preserved
checkouts. Real evidence is admitted and its reference normalized only. Numerical
boundary tests use synthetic outputs. Archive/native/network launch attempts are
refused by the audit guard; the timeout test uses a fake positively owned child.

After tests and source publication, freeze committed clean Q using the same input
arguments and `freeze --grader <HOST_GRADER> --build-identity <BUILD_RECEIPT>
--receipt <STATE_ROOT>/retained-freeze.json --output <FRESH_EXTERNAL_OUTPUT>`.
The operator verifies the build receipt and matching baseline CI before grading.
The freeze binds Q/tree/delta, interpreter, grader, all inputs, normalization and
admission, without spending the grading allowance.

Only then use `grade --receipt <STATE_ROOT>/retained-freeze.json`. Its exclusive
`<STATE_ROOT>/rust011-retained-grading.intent.json` consumes the one allowance
before any real numerical work. Preserve this stable authority directory; a
renamed receipt/output or interrupted attempt never grants another pass. The
CLI has no resume/retry/native/Studio/timing mode. It writes new per-child CPU
attempts/results and a distinct `retained-numerical-requalification.json`.

The 900-second deadline covers the complete pass; each CPU child timeout is
bounded by remaining time, and interruption kills/reaps only that owned child.
The unchanged 256 MiB reference budget observes Python traced allocations and
process peak RSS. Child peak observations are reported separately; neither is an
OS-enforced or continuously observed combined physical cap. Any failure is kept,
with no checker revision or second pass after a failed scientific result.

## Future Studio integration

Studio remains held. A separate work order must select its exact native candidate
and decide admission/release. Fresh native outputs must retain that candidate's
identity; compatibility/numerical checking must carry Q's separate source and host
grader identity. A future caller can use the same strict exact-field semantics,
but this pinned Rust010 retained-artifact validator is not a generic Studio
admission route. C's original frozen qualifier has not been modified. No Studio
campaign or next milestone is implemented here; copying remains the default.
