# Bound checkpoint file admission

`admit_checkpoint_bound(root)` is the file-integrity entry point. Its source-only implementation at `f2705d30b2288dec9c314bc6803ca64a28864766` passed one separately authorized [local verification on 2026-10-05](evidence/bound-admission-local-verification-2026-10-05.md): all 25 pinned files and 106,218,444,193 bytes matched their manifest digests, the catalog parsed 3,215 tensors, and the descriptors were closed. The existing `admit_checkpoint(root)` remains a header-only static inspection helper. The bound constructor rejects catalogs not parsed from the same verified handles. Only a live bound result may feed future runtime page reads; the saved result is historical evidence and cannot reopen or authorize files.

The bound path loads the project-owned pinned manifest, checks its repository, revision, file list, and total size, then opens every listed file relative to one directory descriptor with `O_NOFOLLOW`. It repeats the manifest's full-file SHA-256 for shards and Git-blob SHA-1 for the smaller files using 1 MiB `pread` chunks. In the same pass it records a SHA-256 digest for each chunk. It holds the verified file descriptors open until the bound checkpoint is closed. Config, index, and Safetensors headers are parsed through those descriptors; the acquisition receipt is not an authority in this path.

`BoundCheckpoint.read_page_into` maps a catalog page to exact spans and copies each span through `VerifiedFiles.readinto`. A read checks the directory and file identity (device, inode, mode, size, modification and change times) and rehashes every whole 1 MiB chunk touched by the requested span before copying bytes. A path replacement, symlink, metadata change, short read, or changed chunk fails closed. Callers must discard a partially filled target after any exception. The verified descriptor set is poisoned after an identity or data mismatch, so later reads cannot silently continue. The synthetic fixture adapter has an optional verified mode that exercises this path and stops its pager on failure.

This is a file-byte gate, not a model or memory qualification. It does not execute checkpoint Python, import MLX, allocate model weights, or establish GPU buffer ownership. The 64 GiB host still has a proposed 48 GiB process stop, 40 GiB all-weight cap, and 16 GiB reserve for macOS and other processes. The stock loader remains unsafe here.

The trusted manifest is project source at the reviewed commit. An attacker who can edit source and its manifest can replace the trust root; protect the source revision and inspect its diff before any real run. Some small metadata files currently have Git-blob SHA-1 pins rather than SHA-256; replacing those pins requires a separately authorized read of the real files. The descriptor and chunk checks tolerate ordinary replacement or mutation but do not make the directory immutable, prove device/kernel integrity, or stop a malicious in-process caller from bypassing this API. Per-read whole-chunk hashing may amplify I/O and has not been benchmarked. Derived Python views can outlive fixture accounting, so a production adapter still needs independent memory observation. Real checkpoint digest verification, a production I/O adapter, macOS memory observations, numerical parity, and any inference or benchmark remain separate gates requiring authorization.

The [independent source review](evidence/bound-admission-claude-review-2026-10-04.md) and [local disposition](evidence/bound-admission-review-disposition-2026-10-04.md) cover this design. A generated sub-megabyte Safetensors shard exercises the complete bound admission and page read. The authorized local run qualified file admission only; real page materialization and model execution were excluded. The [next adapter gate](production-adapter-next-gate.md) specifies the remaining ownership, memory observation, and correctness requirements.
