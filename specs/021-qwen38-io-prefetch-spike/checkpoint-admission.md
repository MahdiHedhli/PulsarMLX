## Norm-fold verdict and other numerical gates

**Converted checkpoint verdict: already folded.** The [model card](https://huggingface.co/pipenetwork/Qwen3.8-Flash-Next-MLX-mixed-4_8bit) says the raw reference computes `x/rms * (1 + w)` for centered RMSNorms while the bundled MLX modules compute `x/rms * w`; conversion already added one to those stored weights. The [bundled runtime's `sanitize`](https://huggingface.co/pipenetwork/Qwen3.8-Flash-Next-MLX-mixed-4_8bit/blob/b2c422f3c643e36f04227a64d61796b44a4b1029/qwen4_exp.py) applies `+1` only when raw HF layout markers are present. The native adapter must record the source layout explicitly: multiply the converted centered norm tensor **as stored**, with no second shift; for raw HF weights, add one exactly once. Do not shift gated `linear_attn.norm` or vision norms. The centered suffixes are `hc_norm.weight`, `q_norm.weight`, `k_norm.weight`, `indexer.q_layernorm.weight`, `indexer.k_layernorm.weight`, `ple.norm_key.weight`, `ple.norm_query.weight`, and `ple.norm_conv.weight`. The pinned shard hashes and all 148 centered norm tensors have now been checked; their per-tensor means range from 0.676 to 3.750 across these families, supporting the pre-folded layout. This establishes the stored convention, not output parity.

The [port's analysis](https://github.com/PipeNetwork/qwen38-flash-next-mlx/tree/0352280b927a731fd35276ac622ef2f28da5c936) identifies three further compatibility traps: n-gram hashing defaults to seed **1234** although `config.json` omits `seed` (seed zero chooses different rows); sparse attention prefill beyond the 2048 indexer budget needs per-query visible blocks, the current partial block, and a causal mask; DeltaNet q/k uses exact L2 normalization, rather than a dimension-mismatched RMS shortcut. The published runtime claims tiny-configuration validation against Transformers 5.16. We have inspected those claims and code, not reproduced them. Freeze tiny-fixture numerical tolerances against independently run upstream reference before native implementation. For the I/O-only pager, demand routing IDs/weights, token IDs, and logits must remain identical to the no-prefetch baseline.

## M2 Max capacity snapshot and admission budget

This host is an Apple M2 Max MacBook Pro with 12 CPU cores (8 performance, 4 efficiency), 38 GPU cores, and **68,719,476,736 bytes = 64 GiB** unified memory. `df -Pk /System/Volumes/Data` on 2026-10-03 reported **236,218,800 KiB = 225.276 GiB** free on the internal Data volume (1,948,455,240 KiB total); earlier the same day it showed 213,261,480 KiB. Free capacity is dynamic and unreserved. The checked internal Models path and Hugging Face cache contained no Qwen checkpoint; two Pulsar model paths were symlinks to unmounted external storage.

The exact pinned repository is **106,218,444,193 bytes = 98.924 GiB**; its 11 weight shards account for 106,195,031,237 bytes. The single-copy preflight projected about 126.3 GiB free after acquisition. An *additional*, duplicated 32 decimal GB n-gram scratch file would leave about 96 GiB; design direct reads from the one checkpoint first so the scratch copy is unnecessary. A second whole checkpoint is inappropriate for this disk budget. After acquisition, the internal Data volume had **134,917,525,504 bytes = 125.652 GiB** free; this is dynamic and unreserved.

The delegated approximate n-gram size is **32 decimal GB**; even if all of it stays offloaded, `106.2 - 32 = 74.2 GB = 69.104 GiB` of the published checkpoint remains, already **5.104 GiB above** physical RAM before OS, activations, KV state, I/O buffers or other processes. N-gram paging alone cannot be the design. A provisional **48 GiB total process** ceiling would reserve 16 GiB physical capacity for the OS and other processes. Within that process ceiling, initially allocate no more than **40 GiB to resident model weights/cache** and reserve 8 GiB for KV, activations, I/O staging, and runtime overhead; tune only after measurement. This implies paging at least 58.924 GiB of the 98.924 GiB repository if every file were a loaded tensor, an intentionally conservative upper-bound calculation because the vision tower is unused. This is a planning gate, not a qualified runtime budget. [MLX `set_memory_limit`](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.set_memory_limit.html) is a guideline, not a hard resident-memory limit; [`set_wired_limit`](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.set_wired_limit.html) only bounds wired allocations. Require actual process/OS memory-pressure and swap observations.

## First real baseline sequence (future run, after admission)

1. Keep this branch/worktree separate from the Studio GLM qualification tree. The single pinned checkpoint copy, file hashes, headers, quantization metadata, tokenizer and license are admitted at the static level above. Recheck accepted `main`, disk headroom and the local receipt before any new experiment.
2. Follow the [source-reviewed runtime plan](runtime-execution-plan.md) for an isolated environment and a fail-closed memory gate. Freeze a resolved, hashed dependency lock before installation. Run tiny-config reference checks only after checkpoint-code execution is authorized, independently capturing centered norm, seed 1234, sparse-prefill and DeltaNet behavior against a pinned upstream Transformers reference. The 360 GB BF16 model cannot be a local full-weight reference on this disk. Treat full-checkpoint MLX output as a compatibility reference, not an independent proof of original-model correctness.
3. Do **not** invoke stock `mlx_lm.load` or `mlx_lm.generate` against this full checkpoint on the 64 GiB M2. At the reviewed [`mlx-lm` 0.31.3 loader](https://github.com/ml-explore/mlx-lm/blob/v0.31.3/mlx_lm/utils.py), `load_model` visits every `model*.safetensors`, gathers all weights, executes `model_file`, and defaults to `mx.eval(model.parameters())`; even `lazy=True` does not provide a resident pager. An unmodified full-checkpoint baseline requires a separately qualified larger-memory host. On this M2, build a no-prefetch **paged** baseline first, preserving checkpoint semantics, then compare its I/O-only hinting variant. Start with one short prompt and small token limit for correctness/admission, then a fixed short and long prompt set for latency. Record prompt token IDs, both stop IDs, greedy settings, output IDs, router IDs/weights, selected layer outputs and logits, memory and swap; halt if the reference cannot run inside the memory budget. Do not time the hinting variant until this baseline is stable.
4. Implement and qualify the separate native Qwen graph/MLX affine adapter against independent fixture tolerances and the pinned MLX compatibility output. Record a **native no-prefetch** baseline with the same checkpoint, prompts, and hardware. Only then compare I/O-only lookahead using actual routing as authority. Hold memory budget, decode length, logical cache warmth and OS page-cache condition fixed. Run cold-start, logical-empty/OS-warm and logical-warm/OS-warm strata separately.
5. Emit the [trace contract](trace-contract.md) for each arm. Derive useful, late and wasted prefetch bytes from events; track demand precedence, outstanding requests, buffer lifetime through I/O and GPU completion, cache eviction/pollution, request latency, TTFT, decode p50/p95/p99 and maximum stall, memory/swap, and logical reads. Obtain separately attributed physical SSD reads; mark the metric unavailable if only logical store reads or noisy whole-disk counters exist. The **20+ sustained tokens/s** goal is a target, not a predicted M2 Max result. Reject any output mismatch or sustained swap/p95 regression before considering throughput.

The proposed first correctness packet is one greedy text request with at most 64 prompt tokens and four output tokens; one similarly short request containing an EOS boundary to exercise n-gram reset; and one 2050–2080-token prompt with at most two output tokens to cross the sparse indexer budget. Freeze their **actual token IDs** after tokenizer admission, before loading weights, and run each once without concurrency. Capture route IDs and weights, selected layer outputs, logits and output IDs. Stop on a failed load, unexpected tokenization, output mismatch or sustained swap. These are correctness probes, not throughput samples; any latency sweep follows separately after the no-prefetch reference and native paths pass.
